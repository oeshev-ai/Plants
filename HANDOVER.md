# Чек-лист передачи проекта Plants заказчику

Документ для исполнителя и заказчика: что проверить и зафиксировать при сдаче Telegram-бота и репозитория. Отмечайте пункты по мере выполнения.

---

## 1. Исходный код и артефакты

- [ ] Передан доступ к репозиторию (Git URL, ветка по умолчанию) **или** передан архив каталога проекта с актуальной версией.
- [ ] Заказчик может воспроизвести окружение по **`README.md`** (Python, venv, `pip install -r requirements.txt`).
- [ ] В репозитории есть **`requirements.txt`**, **`.env.example`**, **`README.md`**, **`RUNBOOK.md`**, этот файл **`HANDOVER.md`**.

---

## 2. Секреты и Telegram

- [ ] Заказчик **владеет** ботом в [@BotFather](https://t.me/BotFather) (или получил инструкцию, как создать своего бота и заменить токен).
- [ ] Токен **`BOT_TOKEN`** передан заказчику **по защищённому каналу** (не в открытом чате/email без шифрования — по политике сторон).
- [ ] Исполнитель **не хранит** рабочий токен у себя после передачи, либо старый токен **отозван** в BotFather и выдан новый только заказчику (если токен ранее «светился»).
- [ ] Заказчик заполнил **`.env`** по **`.env.example`** и убедился, что **`.env`** не попадает в git (в проекте он в **`.gitignore`**).

---

## 3. Конфигурация, не являющаяся секретом

- [ ] Зафиксировано значение **`CHANNEL_USERNAME`** в `config.py` (канал для подписи в ответах) — либо уже нужное заказчику, либо заказчик знает, куда править при смене канала.
- [ ] Заказчик понимает: смена канала = правка **`config.py`** + перезапуск процесса.

---

## 4. Запуск и эксплуатация

- [ ] Локальный запуск проверен: **`python bot.py`** (или `python3`) из корня проекта, в логе есть **«Бот запущен.»**
- [ ] Заказчик получил **`RUNBOOK.md`** и при необходимости **unit-шаблон systemd** (или свой способ автозапуска на Windows).
- [ ] Оговорены: **кто** перезапускает сервис при сбоях и **где** смотреть логи (консоль / `journalctl`).

---

## 5. Данные и база

- [ ] Заказчику объяснено: при **каждом** старте бота выполняется полная перезаливка таблицы из **`database._seed_rows()`**; правки только в **`plants.db`** без изменения кода **не сохраняются** после рестарта.
- [ ] Заказчик знает, как добавлять/менять растения: правка **`_seed_rows()`** в **`database.py`** + деплой + рестарт.
- [ ] Ограничение Telegram **4096** символов на сообщение для **`/list`** доведено до сведения (при росте каталога может понадобиться доработка).

---

## 6. Приёмочные проверки (smoke-test)

Заказчик (или исполнитель при заказчике) в Telegram:

- [ ] **`/start`** — приветствие и текст про канал.
- [ ] **`/list`** — список названий с маркерами **•**.
- [ ] Текст с известным растением (например, **Сансевиерия**) — карточка с полями освещение / полив / температура / пересадка.
- [ ] Несуществующее название — ответ «не найдено» (`NOT_FOUND`).
- [ ] Команда вида **`/unknown`** — тот же тип ответа, что для нераспознанного растения.

---

## 7. Права, гарантии и сопровождение

- [ ] Определены **лицензия** на код и **использование текстов** рекомендаций по растениям (если в репозитории нет `LICENSE` — зафиксировать устно/договором).
- [ ] Оговорён срок и формат **постгарантийной поддержки** (канал связи, время реакции) **или** явно зафиксировано «передача as-is без сопровождения».
- [ ] Переданы контакты ответственного с **исполнительской** стороны на период приёмки.

---

## 8. Передача артефактов сессии

- [ ] Закрыты/переданы учётные записи хостинга, CI, секрет-хранилища (если использовались).
- [ ] У исполнителя **нет** единоличного доступа к продакшену без заказчика (при необходимости — отозвать ключи, сменить пароли).
